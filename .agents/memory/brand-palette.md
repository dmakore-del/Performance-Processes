# Brand palette (currently: near-black/white + restrained pink accent, GRAYSCALE B&W imagery)

The palette is **token-driven** in `client/src/index.css` `:root`: `--primary` (near-black `0 0% 9%`), `--background` white, `--foreground` near-black, `--accent` (now **soft blush pink `345 58% 62%`** — lightened June 2026 from the deeper `336 72% 48%`; `--ring` matches), plus secondary/muted/border grays. Changing `--accent` recolors almost every accent usage because components use `bg-accent`/`text-accent`/`hover:bg-accent` (~589 usages).

**Why:** The brand has flip-flopped: original navy+**pink** → migrated to navy+**azure blue** → (June 2026) reverted to **black & white with pink accent**, with the original **pink logo** restored at `client/src/assets/logo.png`. The single highest-impact lever is the `--accent` token plus `--primary`/`--background`/`--foreground`.

**How to apply — where tokens DON'T reach (check these whenever changing brand color):**
- Hardcoded `rgba(...)` radial-gradient glows in page files (`Home`, `Solutions`, `About`, `Consulting`, `Marketing`, `Recruiting`) and `components/layout/PortalLayout.tsx`. Historic values to grep for: old pink `rgba(236,72,153,...)` AND `rgba(236,72,121,...)` (two variants — grep `236,7`); azure `rgba(42,110,240,...)`; current pink glow `rgba(214,30,110,...)`.
- Tailwind **literal** color classes bypass tokens entirely. The azure era used `blue-*` and some `purple-*` (50/100/200/400/500/600/700/900) across portal pages + Solutions value-ladder gradients; these were bulk-converted to neutral `zinc-*` (kept B&W) via a `perl -pi` shade map. When recoloring, grep `(blue|purple|pink)-[0-9]` and `zinc-[0-9]` and decide neutral-vs-accent per spot — do NOT blanket-convert to pink or pink becomes too prominent.
- **GRAYSCALE B&W media (current, June 2026):** all content imagery + videos render black-and-white via ONE global rule in `client/src/index.css`: `img:not([alt="Performance Processes"]):not(.no-grayscale), video { filter: grayscale(100%); }`. The pink logo is excluded by its `alt="Performance Processes"` (every logo `<img>` uses that exact alt), and `.no-grayscale` is an escape hatch. **Why:** the brand has flip-flopped on this — originally B&W, then briefly reverted to "full colour" because the site felt "dull", then the user explicitly asked for **minimalistic high-end B&W** again. The only colour left on the page is the logo + the sparing blush accent. **How to apply:** the alt-based exclusion is load-bearing — do NOT change the logo's alt text or the logo will turn gray; to keep a new image in colour, give it `.no-grayscale`. The Home hero is an autoplaying video (`/assets/videos/hero-team.mp4`, poster `hero-video-poster.png`) of a Black woman professional leading a diverse team. The highest-impact hero/section generated images (hero-video-poster, team-collab-color, workspace-color, team-moving-forward, city-aerial-new, team-strategy-new, collaboration, training) were regenerated as diverse-people + modern-architecture compositions tuned for strong B&W tonality (filenames keep the legacy "-color" suffix but display gray).
- **Mobile-safe autoplay (prod) convention:** every `<video>` carries `autoPlay muted loop playsInline preload="auto"` PLUS the lowercase HTML attr via spread `{...{ "webkit-playsinline": "true" } as any}` (React drops unknown camelCase attrs, so the spread is required for old iOS Safari), and a `poster` image. **Why:** iOS/Android only autoplay muted+inline video; without these, prod phones show a black box or a play button. **Also keep hero video files small (target <~8MB):** the old `hero-atrium.mp4` was ~14MB and was reported as not autoplaying in production — large files stall buffering on mobile/slow networks so autoplay never fires. The poster guarantees a meaningful first frame even if autoplay is blocked, so make the poster carry the key subject.
- **Keep pink restrained:** the request was "pink accent that isn't too prominent." Pink should appear only via the `--accent` token usages (active nav, primary CTA, one highlighted heading word per section, hovers, faint glows). Do not give pink to large filled surfaces or portal status badges — those stay black/gray.
- Accent-on-white contrast for the soft blush `345 58% 62%` is ~3.3:1 — **fails AA for normal text**. Keep blush accent for large/bold headings, hovers, borders, glows; avoid small body-size pink text on white. (The deeper `336 72% 48%` was ~4.7:1.)
- **Decorative icons were removed site-wide (June 2026):** no `lucide-react` outside `client/src/components/ui/*`. Decorative bullets/markers became typographic. Functional affordances **inside `ui/*` only** (dialog close, select/dropdown chevrons, checkbox tick, calendar nav, toast close) were kept. When adding UI, prefer typographic markers over icons to stay consistent.
- **Delicate serif type direction (June 2026):** headings/display use **Cormorant Garamond** (`--font-heading`), body uses **Inter**. `.text-display` = Cormorant 500; `.text-display-italic` = Cormorant italic 400, used for the single blush accent word per headline. Headings are `font-medium`, not bold. Loaded in `client/index.html` Google Fonts link. (Replaced Plus Jakarta Sans / Montserrat.)
- **Punctuation: commas, not em-dashes (user preference, June 2026).** Prose separators use `,` not ` — `. Decorative list bullets use a middot `·` (e.g. OfferCard `includes`, list-item markers), NOT `—`. **Why:** user explicitly asked to replace dashes with commas across the site; em-dash-heavy copy reads AI-generated. **How to apply:** when writing copy, never use ` — ` as a separator; for bullets use `·`. NOTE: a plain `perl -pe 's/—/,/'` silently no-ops on UTF-8 unless you pass `-Mutf8` (regex literal must decode as UTF-8). Em-dashes still linger in JSX code comments (harmless).
- **Homepage = 6 sections with GRAYSCALE B&W imagery (June 2026):** hero (autoplaying video `hero-team.mp4` featuring a Black woman professional, NO eyebrow — the tacky "Growth Infrastructure Studio" kicker was removed) → manifesto (3 pillars) → capabilities (scannable hairline-divided list of 5 + image in intro col, links to `/services#cat-*`) → full-bleed image band (`city-aerial-new.png`) → buyable packages (`getOffersByCategory("packages")` + `OfferCard`, image beside intro) → 4-step process → closing CTA video (`navy-particles.mp4`). Removed: trusted-by strip, fabricated stats, dark before/after, redundant phases, unified-offer video. Footer's fabricated "Our Partners" marquee also removed.
- **Avoid consultant-jargon eyebrow kickers (user: they're "tacky and make clients feel stupid"):** removed the "Growth Infrastructure Studio" (Home hero) and "Growth Infrastructure System" (Solutions hero) uppercase kicker labels. Prefer plain-language section labels; don't reintroduce "Growth Infrastructure …" branded jargon as a visible heading.
